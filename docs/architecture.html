    What stays the same when you switch

    One data layer, two skins

    Lumen reads and writes through the same app/src/state providers and app/src/api client as the current UI. Only the components change, so there's never a second Supabase client or a second copy of the rules.

    Same origin, same session

    Serve both UIs from one Vercel deployment. supabase-js keeps the login in the site's local storage, so switching UIs never asks you to sign in again, and both see the same local cache and sync queue.

    The database enforces the rules

    No overlaps (no_overlapping_activities), ownership (RLS on auth.uid()) and encryption all live in Postgres. Neither frontend can break them, even with a bug.

    Don't drop fields a UI can't show

    Lumen has no quality, symptoms, flag or notes pickers yet. When it edits an activity it must carry those fields through unchanged, or a reschedule from Lumen would erase them.

    The choice is a device setting

    The selected UI is stored per device, like the light/dark theme, under a key such as mindful-me:ui. Nothing about it goes to the database.

    Schema changes follow the workflow

    The migrations Lumen needs (a water metric, hidden categories) are applied to the test project first, then to production before the code ships, per WORKFLOW.md.
